### Why the numbers differ from the handoffs

The handoffs quote 8,872,017 rows after cleaning, FPR 0.0084 and HOIC held-out recall 0.156. Running
the v2 notebook's own code unchanged gives **8,788,935** rows, the same as `train_model.py`. The
quoted figures come from the older `ddos_xgboost_starter.ipynb`, which also loaded `Dst IP`, so its
duplicate check included it and removed fewer rows. The v2 pipeline was kept (v2 is the source of
truth). The model card shows both sets of numbers and explains the difference; the conclusion is
unchanged.

### Evidence from notebook section 9b (`DDoSDetector\app\data\feature_evidence.csv`)

Generated by running notebook sections 0–6 + 9b on a copy. Highlights (attack vs same-day benign):

- Rate (`Flow Pkts/s`, `Flow Byts/s`): attacks are **slower**, AUC 0.03–0.30, so "floods are faster" is contradicted.

- `fwd_bwd_ratio`: supported for HOIC (0.75) and LOIC-UDP (1.00); unclear for LOIC-HTTP.

## 4. Deviations from the handoffs (all also listed in the README or model card)

1. Charts are drawn natively in matplotlib; `shap` only computes values. Reason: `shap.plots` draws on
   pyplot's global figure (its beeswarm colour bar breaks inside Qt).
2. SHAP uses `TreeExplainer` in tree-path-dependent mode (exact). The background sample is saved and
   loaded but not used for explanations.
3. Bulk SHAP (alerts, seed stability) uses XGBoost's `pred_contribs`; a test shows it equals `shap`.
4. Python 3.14 instead of 3.10–3.12 (only interpreter installed; SHAP/XGBoost verified on it).
5. `hoic_held_out` uses the notebook's `per_day` benign split.
6. Extra module `app/core/csv_reader.py` so training and app share the chunked reader; `app/paths.py`
   holds all folder locations.
7. `feature_notes.json` text is a **draft written by Claude** (the handoff pointed to one-liners in
   `train_model.py` that did not exist). Every field is flagged draft in the UI.
8. The LOIC-UDP noise warning in Operational impact is always shown (the handoff's threshold was
   < 1,000 flows, but its example text names LOIC-UDP, which has ~1,730).
9. `--extra-labelled` saves the retrained model as `<mode>_feedback` so the shipped model is not overwritten.
10. Folder layout follows Visual Studio (solution folder + `DDoSDetector` project folder) instead of the
    flat layout in the original handoff.

**Findings:**
- **LOIC-HTTP held out:** recall 0.003 and FPR 0.0055, matching the notebook's 0.003 and 0.0054.
- **HOIC held out:** recall 0.212 with the per-day split, 0.153 with the attack-period split.
- **LOIC-UDP held out is still caught (recall 1.000).** SHAP shows this is almost entirely `fwd_bwd_ratio`, +9.4 log-odds on average. LOIC-UDP flows have a median ratio of about 120,000, while HOIC never exceeds 2.0 and 99% of benign flows are under 1.7, so one extreme feature does the work. This is reported as a stress test on 1,730 flows, not as evidence of transfer. The key message (no transfer to unseen tools) holds for HOIC and LOIC-HTTP; the group may want to soften the wording to "does not reliably transfer".
- **Model stability:** the top feature (`Fwd Pkt Len Mean`) is stable across models, but the rankings differ a lot (lowest Spearman ρ 0.18). The HOIC-held-out models lean on `Flow Duration`, while the others lean on `fwd_bwd_ratio`.
